КОНТРОЛЬНЫЕ ВОПРОСЫ И ОТВЕТЫ

1. Какие роли доступа предусмотрены в GitHub и какие возможности они дают?

В GitHub используются роли Owner, Admin (Maintainer), Write (Contributor), Triage и Read (Viewer). Владелец обладает полным контролем над репозиторием, включая удаление и назначение прав. Admin управляет настройками репозитория, но не организацией. Write может создавать ветки, коммиты и Pull Request, но не менять защиту ветки. Triage работает с Issues и проектами, не изменяя код. Read только просматривает код и создаёт Issues. Такое разделение реализует принцип наименьших привилегий.

2. Зачем защищать основную ветку main и что даёт правило Require a pull request before merging?

Защита main предотвращает случайные и ошибочные изменения, которые могут нарушить рабочую версию проекта. Правило Require a pull request before merging запрещает прямые коммиты: любое изменение сначала попадает в отдельную ветку, затем оформляется Pull Request и проходит проверку. В результате снижается риск поломки основной ветки и обеспечивается прослеживаемость изменений.

3. Чем форк отличается от ветки и зачем внешнему контрибьютору нужен форк?

Ветка создаётся внутри того же репозитория и использует общую историю и права доступа. Форк — это отдельная копия репозитория в аккаунте другого пользователя. Внешний контрибьютор не имеет прав записи в исходный репозиторий, поэтому работает в своём форке, а затем предлагает изменения через Pull Request. Форк изолирует эксперименты и не требует выдавать постороннему участнику права на основную ветку.

4. Что такое Pull Request и как реализуется правило «четырёх глаз»?

Pull Request — это запрос на слияние изменений из одной ветки (или форка) в другую с возможностью обсуждения и ревью. Правило «четырёх глаз» означает, что изменение должно проверить как минимум два человека: автор и ревьюер. GitHub требует указанное число одобрений (в работе — минимум одно), а при включённом Require review from Code Owners — ещё и одобрение владельца затронутых файлов. Слияние блокируется, пока условия не выполнены.

5. Что делает опция Include administrators и почему её важно включать?

Include administrators распространяет правила защиты ветки на администраторов и владельца репозитория. Если опция выключена, владелец может обойти защиту и напрямую изменить main, поэтому правила не гарантируют контроль изменений. Включение опции обеспечивает одинаковые требования для всех участников и исключает «привилегированные» обходные коммиты.
